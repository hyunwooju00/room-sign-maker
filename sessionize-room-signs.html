02 / EXPORT

Get the right Sessionize data

  1. Open your event’s API / Embed page. Create a read-only JSON endpoint, then use Get Code to see its URLs. Sessionize documents this setup in its official API guide.
  2. Use the Schedule Grid view. Choose the JSON Schedule Grid (GridSmart) data, not the public timetable page, a speaker list, or an iCalendar file. The batch kit is built for this specific shape.
  3. Review what your endpoint exposes. Sessionize endpoints do not require authentication. Treat the endpoint URL as sensitive and disable fields you do not need. Download the JSON locally for the offline kit rather than sharing the URL with us.
Why this matters

Sessionize’s API is read-only, but its endpoint URL can expose the data you enabled. The batch kit runs locally; your schedule does not need to be uploaded to a Schedule Press server.

03 / VERIFY

Check the schedule before designing

Sessions are present

If expected talks are missing, check the endpoint’s Includes sessions setting. Sessionize says its default shows accepted sessions only after speakers have been informed.

Rooms and times are present

If rooms or time slots are absent, check the event’s Schedule announced setting. Sessionize notes that a specific endpoint can override this for testing.

Recent edits are visible

Sessionize says API responses may be cached for up to five minutes. Refresh the export after changes and compare a few affected sessions with the organizer’s current schedule.

The venue uses local time

Confirm the date and displayed time on every sign against the venue schedule. Check day boundaries, daylight saving changes and any sessions that move rooms.

The first three checks follow Sessionize’s API troubleshooting guidance. The venue proof is our recommended print check.

04 / BUILD

Build one sign per room and day, then proof it

Choose a format that a person can read at the door: event name, date, room name, ordered start times, session titles and speakers when space allows. Keep the room name visible from a few steps away. Avoid tiny text just to squeeze more information onto a page.

With the free maker, enter one room and day and review the live page. With the Schedule Press batch kit, import the organizer-created Grid JSON and review the generated room/day pages before printing. See fictional A4 and US Letter examples from the free maker. The batch kit has its own sample on the product page.

Give one person the final proof: compare every page’s room, date, first and last session, and any recently changed slot against the source schedule. For larger packs, count the pages you expect: a room used on two days needs two separate signs.

DETAILS

Common questions

Can I use my public Sessionize timetable URL?

No. The free maker uses typed entries, and the Schedule Press batch kit imports an organizer-created Schedule Grid JSON export. A public timetable page is not the required file.

Do I need to announce the schedule publicly?

Sessionize normally hides room and time details when Schedule announced is off. Its API guide describes an endpoint-level override for testing. Review exposure settings before using it.

What if a speaker or room changes after printing?

Refresh the JSON after Sessionize’s cache window, regenerate the affected signs, inspect every changed page, and replace the old sheets at the venue.

Is this affiliated with Sessionize?

No. This guide, the free maker and the paid batch kit are independent of Sessionize. Sessionize’s own documentation is the authority on its API settings.
